# programs anyone can use, overlays that know their place, and checks that look the way a person does

Every Declare program now reaches a screen reader and the keyboard by default: views say what
they are, the library's controls carry their roles, and Tab walks a page in the order it
reads. Menus, dialogs, sheets and toasts are library overlays that open where they belong and
hold the keyboard while they are up. And `declare-verify` boots a program in a real browser,
at a laptop's size and a phone's, and says what a person would find wrong.

## A view says what it is

A view can tell assistive technology what it is with `accessibilityRole` — a word from a closed
vocabulary — and its name, hint, value and state. A role is a contract the compiler holds a
class to: a drawn slider must give its value and range and take `increment()` and
`decrement()`.

```declare-fragment
class Meter extends View [ accessibilityRole = slider, accessibilityLabel = "Volume",
    accessibilityValue = { level }, level: number = 5,
    increment() { level = level + 1 }, decrement() { level = level - 1 } ]
```

The library's controls, menus, dialogs, tables, grids and comboboxes carry their roles, so a
program built from them is accessible with no extra code. On the DOM the views *are* the
accessibility tree: real focus, `inert` behind a modal, live regions, and
`Accessibility.announce` for a handler with no view to speak from. The compiler warns of what
it can see: a control with no name, a control inside a control, content clipped to nothing
but still read, a choice that never says it is chosen. `declare-look --semantics` prints the
tree. A `TextInput` says what it holds with `purpose` (`email`, `password`, `cardNumber`, …),
so autofill and a phone's keyboard know it. The guide gains an Accessibility chapter (19).

## The keyboard reaches everything

Tab visits every control in the order the page reads — the bar before the content, the front
window before the back, a panel only while it is open — and scrolls a long page to where it
lands. In a group that is one Tab stop the arrows move among its members. Esc gives focus
back where it came from.

A shortcut is a record the nearest set takes:

```declare-fragment
keys: Shortcuts [ items = { [ ({ id: "new", key: "N", label: "New" }) ] },
    picked(id: string) { app.openNew() } ]
```

While a menu, dialog or sheet holds the keyboard its keys are its own: a set declared inside
it is in force — a form in a sheet keeps its own shortcuts — and the page's stand down.

## Overlays open where they belong

`Menu`, `Popover`, `Dialog`, `Sheet`, `Toast` and `Window` open in their context's layer — a
window's own, or the App's — open by a verb (`menu.openFor(button)`) or by state (`shown` with
`input`), close on Esc or a press past them, and animate out before they go. A `Sheet` with
`edge = "start"` is a drawer from the leading edge at every width. `present` is true while it
is open or closing, so content built fresh for each opening reads it and stays through the
slide.

## Checks that look as a person does

`declare-verify` boots every program in Chrome at a laptop's size and then a phone's, and
reports what the layout gets wrong: a parent sized by its content that a child spills out of,
text past its box or the window's edge, targets too small for a finger. It lists the classes
the boot never built, which it could not check. A program that never settles is stopped at its
budget and its line quoted, on every browser rung. A misspelled theme token
(`provided("theme").bg`) is a compile error naming the real one.

`declare-look` and assert scripts press as the device does — a finger under `--touch` — and a
finger is not a point: a tap a few pixels from another control is refused, naming it, since a
browser would move it there. A drag can be held open and looked at mid-gesture: `--press`,
`--move`, `--release` (`drive.press`, `drive.moveBy`, `drive.release`).

## Drag and drop asks the tree

`app.viewAt(x, y, except)` answers what is under a point, past the view you name — the ghost a
drag carries, and everything in it. A class name is a value in a body, so a walk up stops at
the kind you want, and is typed as one:

```declare-fragment
onPointerUp(e: PointerUpEvent) {
    let t = app.viewAt(e.rootX, e.rootY, app.ghost)
    while (t != null && !(t instanceof Column)) t = t.parent
    if (t != null) t.accept(this)
    }
```

## Smaller changes

- `WrappingLayout [ columns = { phone ? 5 : 10 } ]` deals equal cells, that many to a row.
- `declare-help map <file>` lists a program's parts with their lines, so a long example is read
  by the parts a task needs.
- A view that clips rasters only its box, however far its drawing reaches.
- A program states its defaults for the platform's flags in `defaultFlags [ render = canvas ]`.
- Programs take a person's files by a dialog or a drop, and upload them as a form.
- The games live in `apps/games` and play on a touch screen, their arcade buttons drawn where
  the panel puts them.
- Declare installed as a project's dependency runs `declare-verify` and `declare-look`.
- `render=gpu` draws with WebGPU from a Rust engine, built on each machine.
